This document defines an OAuth profile for the Linked Web Storage (LWS) protocol. It describes how agents are authenticated, how a client discovers an authorization server and obtains an access token for a storage, and how a storage server validates that access token.

This is an unofficial proposal.

Introduction

The Linked Web Storage Protocol [[!LWS10-CORE]] defines how client applications access and manage resources in a storage. Access to those resources is governed by the identity and permissions of an agent. This specification profiles the OAuth 2.0 Authorization Framework [[!RFC6749]] and related specifications to define the interactions among a client, an authorization server, and a storage server, so that a client can obtain and present an access token for a storage.

An LWS Server and an LWS Client are required to conform to this profile by [[!LWS10-CORE]].

This specification defines conformance criteria for three classes of product: a client, an authorization server, and a storage server. A product conforms to this specification if it complies with all of the "MUST" statements that apply to its class.

Terminology

The terms "authorization server" and "client" are defined by the OAuth 2.0 Authorization Framework [[!RFC6749]].

The terms "JSON Web Token (JWT)" and "claim" are defined by JSON Web Token [[!RFC7519]].

The terms "agent", "LWS Server", "LWS Client", "storage", "storage description", and "storage root" are defined by the Linked Web Storage Protocol [[!LWS10-CORE]].

This specification defines the following terms:

  • authentication credential — a security token that asserts claims about an agent or end user. This token is secured with a cryptographic proof. Examples of authentication credentials include assertions of identity such as OpenID Connect ID Tokens and SAML-based assertions as well as assertions of capability such as ZCAPs.
  • authentication suite — a defined validation mechanism for a concrete serialization of an authentication credential.
