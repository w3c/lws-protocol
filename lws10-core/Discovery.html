Storage Description Resource

A storage description resource provides information a client can use when interacting with a storage, including descriptions of capabilities and service endpoints.

Data Model

A storage description resource is a specialization of a W3C Controlled Identifier document [[!CID-1.0]]. It conforms to the data model defined by [[!CID-1.0]], extended with LWS-specific properties.

  • `id` - the id property is REQUIRED. Its value MUST be the canonical URI of the storage. Per [[!CID-1.0]], this URI is also the canonical URL of the controlled identifier document.
  • `type` - the type property is REQUIRED. Its value MUST be a string that equals Storage or a set of strings that contains an item equal to Storage (case-sensitive).
  • `capability` - the capability property is OPTIONAL. Its value MUST be a set of capabilities, where each capability is described by a map containing the following properties. Additional properties MAY be present.
    • `id` - the id property is OPTIONAL. If present, its value MUST be a URI.
    • `type` - the type property is REQUIRED. Its value MUST be a string or a set of strings.
    • `conformsTo` - the conformsTo property is OPTIONAL. If present, its value MUST be a set of URIs, each identifying a specification the capability implements, as described in .
  • `service` - the service property is REQUIRED. Its value MUST be a set of services, where each service is described by a map containing the following properties. Additional properties MAY be present. The set MUST contain a service whose type equals StorageRoot.
    • `id` - the id property is OPTIONAL. If present, its value MUST be a URI.
    • `type` - the type property is REQUIRED. Its value MUST be a string or a set of strings.
    • `serviceEndpoint` - the serviceEndpoint property is REQUIRED. Its value MUST be a URI.
    • `conformsTo` - the conformsTo property is REQUIRED for the StorageRoot service and RECOMMENDED for other services. If present, its value MUST be a set of URIs, each identifying a specification the service implements, as described in .
{
  "@context": [
    "https://www.w3.org/ns/cid/v1",
    "https://www.w3.org/ns/lws/v1"
  ],
  "id": "https://storage.example/",
  "type": "Storage",
  "service": [{
    "type": "StorageRoot",
    "serviceEndpoint": "https://storage.example/root/",
    "conformsTo": ["https://www.w3.org/TR/lws10-core/"]
  }]
}

Discovery and Binding

All responses to GET and HEAD requests targeting storage resources MUST include a Link header whose target is the canonical URI of the storage, including a relation (rel) parameter whose value equals https://www.w3.org/ns/lws#storage.

Requests for the storage URI MUST return a document that conforms to the storage description resource data model with a media type of application/cid, unless content negotiation requires a different format.

Storage Capabilities

A storage description may contain descriptions of additional capabilities supported by the storage.

A storage that allows clients to change the up link of a Storage Resource, and thereby to move resources between containers as described in , MUST describe a capability whose type equals MoveResource. Clients MUST NOT assume that the up link is modifiable in the absence of this capability. The following properties are defined for a MoveResource capability:

  • `appliesTo` - the appliesTo property is OPTIONAL. If present, its value MUST be a set of strings naming the types of Storage Resource the capability applies to, such as DataResource or Container. If the property is absent, the capability applies to data resources only.
  • `preservesIdentifier` - the preservesIdentifier property is OPTIONAL. If present, its value MUST be a boolean indicating whether the storage preserves the identifier of a moved resource. If the property is absent, clients MUST NOT assume that identifiers are preserved, and MUST rely on the response to the update to determine the identifier of the resource. 
{
  "@context": [
    "https://www.w3.org/ns/cid/v1",
    "https://www.w3.org/ns/lws/v1"
  ],
  "id": "https://storage.example/",
  "type": "Storage",
  "capability": [{
    "type": "MoveResource",
    "appliesTo": ["DataResource", "Container"],
    "preservesIdentifier": true
  }],
  "service": [{
    "type": "StorageRoot",
    "serviceEndpoint": "https://storage.example/root/",
    "conformsTo": ["https://www.w3.org/TR/lws10-core/"]
  }]
}

Storage Services

A storage description resource MUST contain a StorageRoot service whose serviceEndpoint is the URI of the storage root container. The conformsTo property of the StorageRoot service MUST contain the URI https://www.w3.org/TR/lws10-core/, identifying this version of this specification.

Additional services connected to a storage MAY also be present. The API definition of these additional services are outside the scope of this specification. Each additional service SHOULD include a conformsTo property identifying the specifications that define it.

Specification Versions

A client learns which specifications, and which versions of them, a storage implements from the conformsTo property of its services and capabilities. Each URI in a conformsTo value identifies one version of one specification. A specification published by the W3C is identified by the URI of its latest version, such as https://www.w3.org/TR/lws10-core/ for this specification. A later version of a specification is identified by a different URI.

A storage MAY implement more than one version of a specification. A service or capability that does so MUST list the URI of each version it implements; a URI for a later version is added alongside the URI for an earlier version rather than replacing it.

Clients MUST compare conformsTo URIs as whole strings, and MUST NOT derive a version by parsing the URI. Clients MUST ignore URIs they do not recognize, as well as services and capabilities whose types they do not recognize.

A capability without a conformsTo property is interpreted according to the specification that defines its type. For capabilities defined by this specification, such as MoveResource, that is the version of this specification listed on the StorageRoot service.

Authorization servers and the authentication suites they accept are discovered through the WWW-Authenticate response header and the protected resource metadata defined in [[!LWS10-OAUTH]], rather than through the storage description resource, and are not covered by this mechanism.

Storage Description Representation

A storage description MUST be serializable with the media type application/cid [[!CID-1.0]]. The @context property MUST be an array starting with the URIs https://www.w3.org/ns/cid/v1 and https://www.w3.org/ns/lws/v1. Other representations MAY be available via content negotiation. 

{
  "@context": [
    "https://www.w3.org/ns/cid/v1",
    "https://www.w3.org/ns/lws/v1"
  ],
  "id": "https://storage.example/",
  "type": "Storage",
  "capability": [{
    "type": "https://feature.example/PatchSupport",
    "format": {
      "text/turtle": ["application/sparql-update"],
      "application/n-triples": ["application/sparql-update"],
      "application/linkset+json": ["application/json-patch+json", "application/merge-patch+json"]
    }
  }, {
    "type": "https://feature.example/ResumableUploads"
  }, {
    "type": "https://feature.example/ContentNegotiation",
    "source": "application/ld+json",
    "target": ["text/turtle", "application/n-triples"]
  }, {
    "type": "https://feature.example/ContentNegotiation",
    "source": "image/jpeg",
    "target": ["image/png"]
  }],
  "service": [{
    "type": "StorageRoot",
    "serviceEndpoint": "https://storage.example/root/",
    "conformsTo": ["https://www.w3.org/TR/lws10-core/"]
  }, {
    "type": "NotificationService",
    "serviceEndpoint": "https://storage.example/notification/api",
    "subscriptionType": ["WebhookSubscription"],
    "conformsTo": ["https://www.w3.org/TR/lws10-notifications-webhook/"]
  }, {
    "type": "TypeIndexService",
    "serviceEndpoint": "https://storage.example/types/index"
  }, {
    "type": "TypeSearchService",
    "serviceEndpoint": "https://storage.example/types/search"
  }, {
    "type": "DataSharingService",
    "serviceEndpoint": "https://storage.example/sharing/api"
  }]
}
